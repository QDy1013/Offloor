# v0.31 情境演示与操作记录

本轮围绕参赛展示和实际事项的可追溯性继续改进。入口为“更多 → 演示 → 情境演示”。现有日常待办继续使用真实引擎，新的演示页面使用单独的引擎实例。

## 软件中的变化

情境演示逐步调用 Android 应用同一 Engine，完整经过两条新通知、明确改期、含糊变更、本人核对、来源取消和本人完成。核对处可以选择数据库实验报告、物理实验报告或忽略；其余步骤根据引擎的实际状态显示，不预制结果卡片。页面重建通过小型进度检查点重放恢复，演示支持重新开始、查看并复制回放记录。

演示使用构造样例，全程本机处理，不读取账户、真实通知或 AI 密钥，不调用付费接口，不写入真实卡片存档。数据性质在页面和导出记录中标明，不能把该流程回放当作真实用户效果数据。

日常卡片的详情现在显示“来源与处理记录”。人工改标题、核对时间、完成、撤销完成、移除、恢复，以及关联或忽略歧义变更，都会记录执行者、动作和时刻；AI 复核移除标为 AI 操作。关联某项后，其他候选也保留解除待核对的原因。记录保留最近 20 条，事项来源独立显示；旧版本没有记录的操作不补写。

完成和撤销完成统一通过引擎更新，会推进保存版本，也会使操作前的旧 AI 快照失效，避免撤销后又接受旧复核结果。用户反复点同一状态或保存没有变化的字段，不重复生成记录。

另修复图片缓存丢失时队列直接移除的问题。现在保留明确失败说明，提示重新分享截图；不可恢复的图片不会不断重试空路径，旧请求的失败也不能误伤已替换的新图片请求。

## 验证

- 核心、JSON 适配与 Python 检查新增至 77 组；其中 Step53 为 35 项情境、分支与恢复检查，Step54 为 17 项用户操作记录与旧 AI 保护检查。AI 也不能解除仍有未关联变更的待核对状态。
- AiQueueTest 增加缓存缺失、旧请求隔离和不可恢复图片的重试边界检查。
- 既有 20 个独立会话构造场景继续通过，按其既定口径记录，不当作真实准确率。
- `eval/run_showcase.py` 可从 Android 同一场景导出三个分支、每分支七个状态。CI 归档相应 JSON，方便无手机时审查实际引擎结果。
- Android APK 构建与签名、远程 CI、下载验证在交付记录中另外列出。

```sh
python eval/run_checks.py --android-jar <SDK>/platforms/android-34/android.jar --json-jar <org.json.jar> --out core-checks.json
python eval/run_showcase.py --at 2026-11-09T09:00:00 --out showcase.json --markdown showcase.md
python eval/run_reliability.py --out reliability.json
```

本机检查覆盖处理逻辑、存档和构造分支。原生页面在窄屏、放大字体、旋转、后台恢复及真实触屏上的表现仍待设备验证；没有生成或假称已经获得真机截图。真实通知、云端接口和学校账号的验收边界沿用 v0.30 的待验清单。

## 建议的三分钟演示

1. 说明当前是构造样例、独立数据；接收两条通知，查看各自来源。
2. 接收明确改期，指出只有数据库实验报告发生改变，打开记录看修改依据。
3. 接收含糊变更，指出两项原时间被保留；由演示者选择一项或忽略，并查看另一项的解除原因。
4. 接收取消，查看保留的取消来源；由演示者点击完成剩余事项，并查看本人操作记录。
5. 重新开始或改选另一分支，展示结果确实随选择变化。流程演示结束后，单独介绍真实样本和对照评测；尚未取得的效果不写进演示结论。
