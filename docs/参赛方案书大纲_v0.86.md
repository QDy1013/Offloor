## 一、作品摘要与核心主张（约 500 字）

- **一句话定位**：Offloor「楼外」是一款面向高校学生的安卓端系统级日常事项协同助手——**在用户显式授权下，持续从分散的聊天通知、截图与教务系统中维护个人待办，自动追踪改期、取消与群接龙状态，保留完整来源证据，并在课表、待办与学习空间之间形成可执行闭环**。
- **核心差异主张（绝不空喊“首创”，用实测证明差异）**：
  1. 相比传统手工待办 App（滴答清单 / Things）：无需手动抄录与逐条跟进改期/接龙；
  2. 相比“把全部聊天记录扔给云端大模型总结”：本机三级引擎直接消化 **81.0%** 消息（节省 **79.6%～85.3%** 大模型 Token），在严格无泄漏测试集上将截止时间准确率从纯 8B 直抽的 **42.5%** 提升至 **90.0%～92.5%**，含糊时间克制率从 **0%～50%** 锁死至 **100%**，接龙精确率从 **50%～62.5%** 提升至 **100%**；
  3. 相比无状态单条抽取：在 30 组多轮改期/撤回/歧义演进序列中，有状态维护通过率达 **100%（30/30）**，而无状态逐条抽取仅 **23.3%（7/30）**。

## 二、选题背景、真实痛点与赛题二契合度（对应：题材创新 15 分 + 应用价值 20~30 分）

### 2.1 真实校园痛点拆解
- **信息碎片化**：作业、考试、实验、接龙分散在微信群、QQ 群、学习通、雨课堂、教务系统等 5+ 个入口，极易“爬楼漏看”。
- **动态演进陷阱**：初始通知只是起点——更常见的是“推迟到周五”“改到教西 D-204”“取消”“30 人接龙你还没接”，静态待办工具无法持续同步这些变化。
- **跨源决策割裂**：收到一条周四晚考试或作业截止后，学生还要切回课表看是否撞课、算今天哪段空档可以自习、再去查空教室或预约图书馆研修室。

## 三、创新方案与体验设计（对应：解决方案创新 15 分 + 体验设计创新 10 分）

### 3.1 端侧三级引擎 + 端云非对称协同架构
- **配图建议**：直接插入 [系统架构与模块说明.md](系统架构与模块说明.md) 中的 Mermaid 分层架构图。
- **核心创新点 1（本机三级优先 + 零跳动交互）**：第 1 级噪声过滤与确定性时间/接龙/改期状态机 → 第 2 级 40KB 轻量逻辑回归（8 维特征 + 字符 2-gram）→ 仅约 19% 边界样本进入第 3 级队列。
- **核心创新点 2（三道防幻觉护栏 + `v0.86` 端侧非对称权限策略）**：
  - 采样期 `LocalLlmCore.judgeGrammar(n)` 有限状态 GBNF 语法约束；
  - 解析期 `parseDeadline + deadline_evidence + grounded()` 逐字证据校验；
  - 写回期 `v0.86` 非对称权限：端侧 1.5B 仅负责已有待确认卡片的标题与字段补全（跳过未出卡复判，根治小模型迎合误报并再省 31.6% 端侧推理量），云端/较大模型才承担未出卡漏报召回。
- **核心创新点 3（有状态演进与歧义克制）**：支持改期更新原卡、撤回溯源、本人接龙后自动消卡；当同日多场考试或相似待办指向不明时，拒绝静默改错，高亮「待核对」交由人工拍板。
- **核心创新点 4（跨源学习与校园闭环）**：将教务课表自动同步进识别上下文（课程名匹配），实现**按考试持续时段区间重叠判定撞课**，并在本周课表页提供轻量自习空档条，一键预填跳转空教室查询或图书馆研修室预约。

## 四、软件技术实现与性能评测（对应：软件技术 25~30 分）

### 4.1 架构与模块复杂度（面向 AI 辅助代码评测）
- 引用 [系统架构与模块说明.md](系统架构与模块说明.md)：`109` 个原生 Java 类、`25,627` 行代码、零第三方重型框架、签名 APK 仅 `2.46 MB`（含 `liboffloor_llm.so`）；`v0.86` 将首页清晰解耦为 `MainActivity`、`HomeCardSheets`、`HomeOpsSheets`、`HomeConflictState`、`HomeSourceStyle` 5 个高内聚模块。

### 4.2 关键技术难点攻克（用实测消融说话）
1. **同集 8 路对照实验（100 条冻结无泄漏集 `eval/strict_ood.jsonl`）**：直接引用 [同集对照与端侧消融报告.md](同集对照与端侧消融报告.md) 总表：
   - 纯本机 APK Java 引擎：F1 **95.9%**、时间准确 **90.0%**、含糊克制 **100%**、接龙 **100%/100%**、0 Token；
   - 本机 + 端侧 1.5B（`v0.86` 非对称护栏）：相比加护栏前精确率由 `88.9% → 97.9%`（+9.0pp）、F1 由 `92.3% → 95.9%`（+3.6pp）、推理消息再省 `31.6%`（`19 → 13` 条），相比纯 1.5B 直抽节省 **85.3% Token**；
   - 本机 + 参考 8B 协同：相比纯 8B 直抽节省 **79.6% Token**，F1 `89.9% → 95.0%`，截止时间准确 `42.5% → 92.5%`（+50.0pp），含糊克制 `50% → 100%`，接龙精确 `62.5% → 100%`。
2. **GBNF 语法约束消融（19 条真实升级 / 7 批）**：
   - 无 GBNF 时 1.5B 有效条目仅 **`5.3%`（1/19）**（8B 为 `84.2%`），开启 `LocalLlmCore.judgeGrammar` 后双双达 **`100.0%`（19/19）**。
3. **多轮状态演进对照（30 场景 / 39 检查点）**：
   - 连续有状态维护 **30/30（100%）** vs 无状态逐条抽取 **7/30（23.3%）**，零误改受保护目标（22/22）、100% 检出歧义（6/6）、100% 撞车检查（8/8）。

### 4.3 真机硬件配置与程序性能实测
- **实测平台**：vivo V2505A（Android 16 / SDK 36，arm64-v8a，支持 `asimddp`/`i8mm`/`bf16`）。
- **端侧 1.5B 推理实测**（`Qwen2.5-1.5B-Instruct Q4_K_M`，`1.04 GB`）：单次冷加载试跑 **`2.927s`**，温态 **`2.357s`**，单次峰值 PSS `1.79 GB`；`v0.86` 连续 5 轮加载-推理-释放压测耗时 **`2.87s ～ 2.93s`**，释放后 PSS 稳回 **`164.6 MB`**（Native Heap `75.6 MB`，零泄漏），机身电池温度 **`36.9°C → 36.9°C`（+0.0°C）**，`0` 崩溃 / `0` ANR。
- **端侧本机识别引擎延迟**：JVM/端侧规则与 40KB 线性分类器单条毫秒级响应，不阻塞主线程与通知栏。

## 五、软件工程质量、安全合规与诚实边界（对应：软件工程质量 15~20 分）

- **版本演进可追溯**：Git 提交完整记录 `v0.9` 至 `v0.86` 迭代轨迹（见 [CHANGELOG.md](../CHANGELOG.md)），GitHub Actions 自动跑全量单测并按提交发布带 NDK 推理库的签名 APK。
- **自动化回归体系**：`95` 组核心/适配器单测 + `19` 组页面与视觉契约检查 + `30` 组多轮状态序列 + `20` 组边界可靠性检查 + `3` 条 7 态演示状态机导出。
- **隐私与数据安全**：校方凭据与 API Key 采用 Android Keystore + AES-GCM 加密；启动自动清理 30 天前已完成/已移除记录；「复制同步自检」经 `CampusDiag` 严格脱敏零敏感字段；系统日历不写入群原文。
- **AI 辅助开发与贡献声明（官方明确鼓励并要求披露）**：
  - 明确说明团队负责需求洞察、产品交互审美把控、三级架构与状态机设计、测试基线冻结、西工大真机调试与验收决策；
  - AI 编程助手参与代码实现、自动化测试用例编写、重构与文档整理；所有算法结果与真机表现均经本地/真机实际运行验证，未伪造任何数据。
- **诚实局限声明（绝不夸大）**：
  - 未进行 BERT 微调、云端蒸馏或 LoRA 训练；
  - 仅读取系统通知栏可见文字，已移除无障碍读屏，免打扰群与未展示正文消息需靠「主动分享截图 OCR」补充；
  - `strict_ood.jsonl` 仍为手写代理集，真实班级群多用户大样本与中低端机型连续耗电测试列为下一阶段工作。
