# 研修室预约改进

这版没有新增权限，也不改校方协议：仍然是「按需连接、手动确认、写请求不重试」。
改的是把一个能用的功能做到用起来顺手的程度——从「先猜时间再被校方拒绝」变成「看见能约的时段再点」。

## 界面

- 顶部一张状态卡：连接状态、数据更新时间、错误原因、「上次结果未核对」的提示都收在一起；未连接时只给三个动作（重新连接 / 打开校方页面完成验证 / 更换账号）。
- 「看空闲房间 / 我的预约」改成轨道上的分段按钮，右上角一个刷新图标替代原来的整块「刷新校方数据」按钮。
- 日期快选：今天到第 7 天直接横着点，更远的日期走日期选择器（只能选今天到 30 天后）。选中的日期在快选条之外时，会额外补一个当天的胶囊。
- 房间卡片：名称 + 「可预约 / 暂不可约」标签、位置与类型、人数与时长规则、开放时间、占用摘要；可预约时直接给出三个可点时段，点一下就带着时间打开预约面板。
- 「我的预约」卡片：状态用颜色区分（使用中绿、待同行人确认琥珀、已结束灰、违约红），并给一句「还有 2 小时开始 / 正在使用，剩 40 分钟 / 已结束」，可以一键复制预约信息。
- 空列表、翻页、错误都有各自的说明，不再用一块空白让人自己猜。

## 时段

新增 `StudyRoomPlan`（纯逻辑，不依赖 Android）：

- 以开放时段的起点为基准，按校方的 `timeInterval` 对齐生成时段；默认给 60 分钟，夹在 `minResvTime`–`maxResvTime` 之间。
- 扣掉已占用区间，并且把校方的冻结间隔（`freezingTime`）也算进去，所以不会推荐一个「看着空、提交被拒」的时间。
- 已经开始的时间直接不出现；当天剩余时间不足一个默认时长时，只在校方最短时长够用时给一个缩短时段。
- 选开始时间后，结束时间只在合法范围内按间隔给出，避免 `09:10–10:10` 这种被校方打回的输入。

## 提交前

- 面板顶部预填时段，点开始 / 结束都是选项列表，不是自由输入。
- 实时校验：结束晚于开始、开始不在过去、整段在开放时间内、时长在规则内、人数在 `minUser`–`maxUser` 内、不与占用重叠；任何一条不满足就把原因写在时段下面，直接说清楚差在哪。
- 时间冲突提示：与自己已有的研修室预约、以及已导入课表当天的课做重叠判断，命中就提示「时间冲突：「高等数学」08:00–09:40，请确认是否仍要预约」。**只提示不拦截**——课表可能不准，最终由你自己决定。
- 同行人仍然只能从校方通讯录里搜出来添加，最多 30 位；移除是逐个点掉，不靠手输。
- 预约须知默认折叠四行，点一下展开全文；验证码图片按原始比例显示，比原来 64dp 的固定高度看得清。

## 提交后

- 勾选「在首页加一条开始前 2 小时的提醒」（默认勾选）后，**只有校方明确受理成功**才会写入首页任务，复用现有的到期提醒；结果未知或失败时不写，宁可少一条提醒也不留错的。
- 成功后自动切到「我的预约」并刷新，可以直接核对状态。

## 容错

- 修掉一处会把用户永久挡住的 bug：写请求如果因为会话刚失效而根本没发出去，现在会把「未核对」标记撤回；以前会一直停留在「请先核对上次操作结果」。
- 不可预约的原因来自校方数据本身（规则没读全 / 没有开放时段 / 占用没读全 / 课表没读全 / 仅可查看 / 人数没读全），界面直接显示，不再只说「暂不可约」。
- 校方返回的时间字符串统一按中国时区解析，`2026/11/12 09:30`、带毫秒、带时区后缀都能认；认不出就当解析失败，不猜。
