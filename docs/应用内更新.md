# 应用内更新（v0.22）

## 使用

入口：主页面“更多 → 下载最新版”、校园页右上角“校园设置 → 下载最新版”，以及课表登录页右上角“更新”。点击后直接查询线上最新发布信息并开始下载当前渠道的安装包，不要求登录校园账号。

更新页显示当前和线上版本、下载字节数和进度。系统DownloadManager负责下载，离开应用不取消任务；再次打开更新页可恢复查看正在下载的任务。网络失败、文件被移除或校验失败可以重试。同一版本也允许重新下载。

完成后点击“安装更新”交给Android系统确认安装，应用不会静默安装或卸载原版。Android首次安装可能要求允许此应用安装未知来源软件，页面会跳转到对应系统设置，返回后继续校验并打开安装程序。

旧安装包没有更新按钮，需要先安装一次v0.22，之后可使用应用内入口。安装包必须与原应用具有相同包名和签名才能覆盖更新。本轮正式版沿用原正式版签名，测试版沿用原测试版签名，两者分别匹配，不互相替代。

## 发布地址与渠道

客户端读取公开目录：

```text
https://raw.githubusercontent.com/QDy1013/Offloor/updates/latest.json
```

目录按安装包ID选择，APK保存在 `updates` 分支中按SHA-256命名的路径，旧版本目录可继续存在，避免发布期间目录和下载文件不一致。

| 包名 | 渠道文件名 |
|---|---|
| `com.nopalou` | `offloor.apk` |
| `com.nopalou.preview` | `offloor-preview.apk` |
| `com.nopalou.timetabletest` | `offloor-timetable-test.apk` |

`latest.json` 包含 `schema: 1` 和 `packages`。每个渠道包含 `versionCode`、`versionName`、`size`、`sha256`、`certificateSha256`、`url` 和更新说明 `notes`。只接受本仓库更新分支、摘要路径和当前包名对应文件名，拒绝线上版本回退、异常大小、渠道错配和签名不兼容。

APK下载到应用自己的外部文件目录，无需申请共享存储权限。下载完成及安装前都核对摘要、长度、实际包名、版本和签名；安装使用DownloadManager的受限 `content://` URI和临时读取授权，不暴露 `file://` 路径。

## 后续发布新版

1. 增加Manifest中的版本号，使用各自原签名构建需要更新的渠道。
2. 准备发布目录，已有线上目录时用 `--existing` 保留其他渠道：

```text
python android/prepare_updates.py --sdk <SDK路径> --out <发布目录> --apk <正式版APK> --apk <测试版APK> --apk <课表测试APK> --existing <原latest.json>
```

初次发布可不传 `--existing`。脚本读取真实APK包名、版本和签名，并再次验证APK签名，复制到内容摘要路径后生成目录；不会复制密钥。已有目录时拒绝覆盖成更旧版本或不同签名。

3. 将生成的 `latest.json` 和新 `apks/` 文件以同一次提交发布到仓库的 `updates` 分支，保留旧摘要目录。用户下次点击按钮就会下载新版本；仅修改源码或构建本机APK不会自动发布到更新渠道。

## 验证与范围

新增JVM检查覆盖当前渠道选择、版本回退、异常来源、摘要路径、非法大小、损坏/截断文件和实际包名/版本/签名替换。发布脚本直接读取本轮三个渠道真实APK的版本和签名；发布后重新从公开下载地址获取文件并核对长度及SHA-256。

2026-11-08已连接测试手机，验证同签名覆盖安装后课表和校园存档保留。正式0.26版从校园设置点击“下载最新版”，成功获取线上0.26安装包，应用显示“最新版安装包已下载”“校验通过”，提供“安装更新”按钮。下载管理器通知、断网恢复与退出应用后恢复进度尚未逐项实机验收。

平台依据：[Android DownloadManager](https://developer.android.com/reference/android/app/DownloadManager)、[安装来源设置](https://developer.android.com/reference/android/provider/Settings#ACTION_MANAGE_UNKNOWN_APP_SOURCES)。
