# 演示与答辩要点（v0.85）

本文面向现场演示与评审问答。所有评测数字以 [README.md](../README.md) 与 `eval/benchmark_report.json` 为准，严格区分 **APK Java 实跑引擎** 与 **Python 参考实现**，不沿用历史过时数字。

## 30 秒讲清价值

高校学生的任务分散在微信/QQ 群、学习通/雨课堂和教务系统里。Offloor「楼外」以**本机三级引擎优先**（无泄漏分布外 100 条上 **81.0%** 由 APK 本机直接消化，F1 **95.9%**），实时把群通知整理成可溯源待办、考试与群接龙，自动追踪改期、取消和已接龙状态；低置信或残缺消息才交给**端侧 1.5B 小模型（`llama.cpp` + GBNF）**或可选云端模型复核；并把教务课表与待办打通——预警撞课撞车，在课表页一键把今日空档预填到**空教室查询**与**图书馆研修室预约**。

## 演示前检查

1. **核对版本与包体**：确认手机安装的是 `v0.82` 正式/预览包（设置或关于页可见版本号）；若安装独立测试包，其数据与正式版隔离。
2. **核对通知权限与保活**：打开「自动读取自检」检查通知使用权、监听连接、电池白名单与自启动提示。提前向评委说明：监听连接正常不等于免打扰群或未给正文的通知都能读取。
3. **检查端侧/云端 AI 状态**：默认关闭 AI 即可完整演示本机引擎；如需演示端侧 1.5B 推理或截图转写，提前确认 GGUF 模型已导入或云端测试接口已联通。
4. **区分离线演示与真机同步**：使用内置「情境演示」或独立回放器时，主动说明是离线样例回放，不是实时抓取真实微信；校园余额（电费/网费/一卡通）演示前确认校内账号已登录。
5. **备好演示录像**：不能把 95 组 JVM/Python 与 19 组浏览器回归通过等同于所有安卓/鸿蒙机型保活和交互都已实测通过。

## 评审高频问答

**1. 真实群聊泛化效果如何？**

目前尚未采集脱敏后的真实班级群聊数据集。我们公开两套透明基准：
- **100 条无发送者泄漏分布外集（`eval/strict_ood.jsonl`）**：APK Java 引擎与 Python 流水线均达到 **召回 94.0%、精确 97.9%、F1 95.9%、截止时间准确 90.0%、含糊时间克制 100%、接龙召回 100%**，相比纯关键词基线（F1 71.4%）大幅领先，且 Java 引擎 **81.0%** 无需调用大模型。
- **8,086 条合成时间切分留出集**：Java 引擎 F1 **97.41%**（时间准确 **93.25%**），Python 版 F1 **97.83%**（时间准确 **92.40%**，变更准确 **80.85%**）。我们明确标注该合成集有 **82.32%** 文本在训练集出现过，仅做双端一致与回归验证，不作为真实群聊泛化证明。

**2. 到底用了什么模型？有没有微调或蒸馏？**

- **第一/二级（常驻本机）**：规则状态机 + 8 维特征与字符 2-gram 轻量逻辑回归（权重约 40KB，`model.tsv`），零延迟消化 80%+ 消息。
- **第三级（按需兜底）**：APK 已通过 NDK 编入 `llama.cpp` 原生库（`liboffloor_llm.so`）与 GBNF 结构化 JSON 约束，在真机 vivo V2505A（Android 16）上实测 `Qwen2.5-1.5B-Instruct Q4_K_M`（1.04 GB）冷加载试跑 **`2.927 秒`**（温态 `2.357 秒`），峰值 PSS `1.79 GB` 且推理结束自动释放回 `256.8 MB`；同时也支持用户自行配置 OpenAI 兼容云端接口与截图视觉转写。
- **诚实边界**：**没有**做 BERT 训练、**没有**做云端蒸馏打标，也**没有**做 LoRA/QLoRA 微调；中低端机型分机型速度、持续多批耗电与「端侧 1.5B vs 云端」同集质量对照仍待补充。

**3. 隐私和合规怎么保证？能不能说“数据绝对不出手机”？**

**不能**笼统说绝对不出手机，而是分层明确边界：
- 默认关闭云端 AI 时，通知识别完全在本机运行；开启云端 AI 后，仅待复核原文、上下文或用户主动分享的截图会发往用户自己配置的接口。
- 校方账号凭据使用 Android Keystore + AES-GCM 加密存本机；启动时自动清理 30 天前已完成与已移除记录（未完成待办保留）；写入系统日历不含群消息原文；「复制同步自检」严格剔除学号、余额数字、密码与临时令牌。
- 图书馆研修室绝不后台抢约、绝不绕过验证码、写请求不自动重试；缴费只跳校方官方页，不代收卡密。

**4. 能不能保证一条群通知都不漏？**

不能。系统只读取 Android 通知栏实际弹出的文字，不使用无障碍（AccessibilityService）强行爬屏，也不读取聊天数据库或语音文件。免打扰群折叠、聊天软件未展示正文、手机厂商杀后台都会导致缺失；我们提供自启动/电池引导、看门狗重连以及「分享截图 OCR」作为用户主动补充路径。

**5. 临时改期或撤回指向不清时怎么防止改错？**

仅响应可信发送者（老师/助教/班委等线索），屏蔽纯星期/时段词引起的跨事件误匹配（例如「本周五班会取消」不会误撤同日体检回执）；若多张相似待办或考试得分打平，保留原时间并高亮「待核对」交由人工确认；用户手动修改过的内容绝不被后续 AI 复核覆盖。

## 现场应急预案

- **通知未连接**：点击首页「自动读取自检」按机型提示补授权限；若现场机型受限，直接切换到内置「情境演示」或预先录制的真机视频，并明确告知评委。
- **校园网波动导致教务/余额同步慢**：使用已缓存的本地课表与校园快照展示完整交互，并可演示右上角「复制同步自检」如何零隐私定位故障。
- **无图/无正文消息**：若已配视觉模型可演示主动分享截图转写；不宣称支持已移除的无障碍读屏功能。
