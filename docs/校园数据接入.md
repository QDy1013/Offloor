# 校园数据接入（v0.24）

本轮目标：把正常登录后本人可见且能识别的信息接入 Offloor，提供原生离线展示。新增代码和安装包已构建；用户本轮无法连接测试手机，新增个人数据没有进行真实账号验收。不能把下列服务目录当成全部接口已接通。

## 使用

输入一次翱翔门户账号密码后，应用自动连续读取课表、考试、各学期成绩、绩点、学籍和校园服务，完成后直接进入校园总览。用户无需再点击“全部同步”、逐项打开服务或点击“读取此页”；这些手动入口已移除。底部“校园”用于查看字段、表格、公告链接及最后一次成功读取的时间。

v0.24先保存课表和已确认的本人身份，历史成绩移到并行队列中读取，不再挡住登录完成。最多三个浏览器同时处理不同站点；同站点页面避免重复导航，历史成绩的只读API与其他教务页面可同时处理。门户先建立一次公共会话，只有服务实际需要时才重试统一认证；取消门户固定6秒和逐页固定1秒等待，改为观察请求、DOM变化及稳定结果。脚本按文档注入，成绩没有变化时只轮询状态，不反复传输整份历史。

结果分批保存，校园页和成绩页自动刷新。可点“先查看已读信息”正常浏览应用，剩余读取继续；完成后不打断当前页面。原生登录、读取进度及内容页面统一使用正体无衬线字体，重置倾斜，统一字体留白、居中和混合字号的行对齐。此处为实现说明，真实手机的速度和显示仍待验证。

后续进入应用自动复用校方会话刷新，成功批次间隔6小时，部分失败10分钟重试；应用停留前台时每分钟检查是否到期，后台不启动浏览器。取消批次后等待2分钟再尝试，升级版本后自动刷新。一次只运行一个批次，旋转或进程恢复可重新读取当前模块；密码不保存，校方会话真正失效时才需要再次统一登录。各系统自己的会话由同一个CAS登录建立，不要求分别输入密码。

应用共用WebView的校方会话存储，采用顶层页面跳转建立各服务自己的会话。门户中观察到的链接、应用目录名称与URL、校方统一认证按钮及应用图标用于正常认证交接；只触发匹配服务的普通页面事件。应用图标异步获取票据并使用 `window.open` 时，将其受信任的校内导航保留在当前WebView，不导出或保存票据。没有为各个系统编造CAS服务地址，也没有把同一个密码转发给不同业务站点。

CAS中转页先等待跳转。只有统一认证站点的密码表单稳定出现，才自动转入一次重新统一登录，之后继续读取。业务站点出现密码框时，先查找其统一认证入口，并重试门户入口；仍没有找到时标记为入口待适配。校方验证码或二次验证会显示校方页面，完成后自动继续，不作为“另一个账号”处理。

自动驱动器进入校方页面上可识别的个人信息、消费明细、借阅和预约记录等只读菜单，执行“查询/搜索”，等待加载及内容稳定，逐页读取已观察到的“下一页”，合并去重后保存。优先选择“全部/不限”，没有全量选项时遍历页面实际提供的学期、年度、状态等筛选组合，支持原生select及Element/Ant等组件菜单。自动进入记录详情、返回列表后继续读取；不同记录和学期分别保留，兄弟页面不会因离开当前页而漏掉。支持已识别的虚拟滚动列表、ARIA表格及多个校方只读iframe。正常批次只显示读取进度；验证码出现时显示校方页面。入口未适配、网络失败、加载占位或未识别页面如实显示状态并继续其他模块，保留上次成功数据。不会把空白页面误报为读取成功。

不再只依赖固定的16项服务。门户实际返回的其他校内应用会进入账号绑定的目录，自动加入队列，并在“门户中的其他服务”单独展示；没有可持久化读URL的应用图标仍使用正常门户点击事件打开，不保存临时票据。账号切换也清除这一目录。目录发现及通用读取不等于每个新应用都已有专用接口验收，不能将未识别页面标为成功。

App不提交选课、评教、续借、预约、取消、充值或支付。只跟随校方实际提供的读链接和限定菜单，不猜测未提供的接口。通用适配并不能保证覆盖所有站点结构和所有历史筛选范围，仍需真实账号验证并按具体页面补充专用适配。

先读取“我的宿舍”和学工信息，再将明确的本人住宿校区、楼栋和房间字段与校方返回的实时 `name/value` 选项唯一匹配，匹配成功自动查询电量并保存绑定。已绑定时直接查询；绑定失效会尝试重新匹配。校方没有提供住宿信息或存在歧义时，只跳过电量，不中断其他模块；电量详情可补充一次本人宿舍，后续自动查询。不会猜测住址或批量枚举房间。

信息按“字段 / 表格 / 链接”展示；表格每次展开30条。每模块最多80张表、每表10000条、30列，每个单元格最多600字；最多2000个字段、400条链接、1000次只读动作。资源或循环保护触发时明确标为部分读取，不伪装成全量完成。单模块缓存上限约4百万字符，总存档24MB，门户目录最多120项。结构化正文及附件链接也会自动保存；PDF/Office附件正文与扫描图片未解析。不会遍历全站、不保证覆盖全校所有系统。新页面或变更结构可继续增加专用适配器。

## 存档与失败处理

`campus.json` 使用应用私有目录和 AtomicFile，带大小上限；每个模块保存自己的成功时间，本次失败保留原内容和原成功时间，另记失败状态。空白、认证页和纯加载页不能覆盖成功存档。新版本内置本轮验证过的公开公告链接快照，带采集时间，可在安装后离线查看；个人信息必须本人登录后同步。

分批返回的部分结果先与旧记录合并，读取完整后以本次全量结果替换。历史成绩逐学期隔离错误；某个学期失败时保留它的旧结果，同时保存其他成功学期的新结果，包括校方明确返回的空学期。失败与部分状态会显示并触发自动重试。

学生身份仅以学校范围内的 SHA-256 标记用于账号隔离。显式换账号时清除旧 WebView 会话；确认新学生身份后清理旧账号模块及宿舍绑定。其他页面的异步保存检查启动时的账号标记，拒绝旧账号的迟到结果。

仅允许 HTTPS 西工大域名导航与受限读取；登录凭据不由新模块读取/导出，无 JavaScript 原生桥。只从已观察到的链接发现入口，拒绝包含认证票据或明确写操作的自动链接。排除密码、验证码、身份证、家庭信息、银行卡、支付码等标签/列，以及脚本、隐藏输入和隐藏单元格内容。没有把真实个人账号、Cookie、密码或个人页面写入仓库。

- v0.21新增 `test_nwpu_sso.cjs`：12项，使用合成统一认证与两个合成服务验证共享浏览器会话、独立服务会话、普通认证跳转、入口发现、只触发一次官方按钮及异步应用图标导航。所有认证测试均为合成环境，没有使用真实账号。浏览器拦截环境用页面导航模拟认证重定向链，未替代真实服务验收。
- `CampusAuthTest`：10项，覆盖瞬时中转页、稳定中央登录表单、验证码等待和业务登录入口的分类。累计160项检查通过。
- 真实公网仅验证了公开公告HTML、网络登录入口和电量校区选择查询的状态。新增个人模块、真实跨系统SSO、各设备原生界面及校园网环境尚待验收。
- v0.23新增 `test_nwpu_auto.cjs`：15项，在真实Chromium的离线合成页面中自动进入消费明细、查询、读取三页、等待网络请求、识别空结果、匹配拆分表头、进入iframe及触发SPA菜单，不执行写操作。
- v0.23新增 `CampusAutoTest`：24项，覆盖登录后自动衔接、重复批次抑制、刷新/失败重试/版本升级时机、稳定后读取、分页去重、明确空结果覆盖旧数据及宿舍唯一匹配。校园提取17项、SSO 12项、存档14项、认证分类10项回归通过。这些结果不等于真实学校账号已验收。
- v0.24：浏览器自动读取测试增至25项，覆盖跨学期、全状态查询、组件下拉框、详情弹窗、动态应用目录与虚拟列表；`CampusAutoTest`增至37项，覆盖兄弟页面队列、详情上下文、分批合并、动态模块账号隔离及三路调度。成绩JS 21项，成绩模型17项（另可传浏览器输出做衔接检查）。
- 受控Chromium耗时对比：三个离线合成站点，各查询并读取三页，共9条记录；模拟旧串行800ms轮询约20.1秒，新并行100ms轮询约1.26秒，结果一致。此为浏览器模拟，不是Android或真实校园服务器测速。`eval/test_nwpu_speed.cjs [v0.23的nwpu-auto.js]`可重现相同类型对比。

运行浏览器检查需Playwright及Chromium。可通过环境变量 `PLAYWRIGHT_MODULE` 指向已有Playwright模块、`CAMPUS_BROWSER` 指向Chrome/Edge可执行文件。JVM检查使用项目原有的 `org.json` 测试类路径。`inspect_campus_public.cjs` 可对下载的公开HTML做无网络真实DOM验证。

## 构建

```text
python android/build.py --sdk <SDK路径> --preview --keystore <已有测试签名密钥库> --out <输出目录>
```

应用ID `com.nopalou.preview`，版本0.24，可与原版并存；复用原测试密钥以便兼容已有测试版。测试版本的存档和校方会话与原版分开，在测试版统一登录一次即可开始自动读取。三个渠道安装包沿用各自旧签名，并发布至应用内更新目录。不能因为源码构建通过而宣称所有服务已实际抓取成功。
