# 电费与网费：金额显示、低余额提醒、缴费入口

v0.41 起，校园页的余额按“钱”来显示和判断，并补上缴费入口。

## 能做什么，不能做什么

| 能力 | 状态 |
| --- | --- |
| 读取校方电费（剩余电量）、网费余额 | 已有，沿用原来的读取通道 |
| 电费显示成金额 | 新增：按可配置电价折算，同时保留度数 |
| 电费低于阈值提醒 | 已有雏形，本次改为按金额判断 |
| 网费低于阈值提醒 | 新增 |
| 跳到校方官方缴费页缴费 | 新增：应用内嵌官方页面 |
| **在应用里直接扣款/代收** | **不做，也做不到** |

代扣需要校方授权的支付接口和支付凭据，本仓库两者都没有；把金额、卡号、密码收进 App 再自行提交，风险远大于收益。所以缴费一律发生在校方自己的页面里，App 只负责把用户送到那里。

## 电费为什么能“按元算”

校方电费页只给**剩余电量（度）**，没有任何金额字段。因此换算：

```
金额 = 剩余度数 × 电价（元/度）
```

- 默认电价 `0.5 元/度`，可在「成绩、课表与余额提醒」里改；
- 电价只接受 `0.05–20` 元/度，填错就退回默认，不拿坏参数算钱；
- 显示为 `¥11.00`，下面一行补 `22.0 度 · 按 ¥0.50/度`，方便和校方页面对照；
- 页面明确标注“仅供参考，以校方账单为准”——换算值不等于校方账单。

读不到电量时显示“电费暂未读到”，**不补零**；读不到也不会触发提醒。

## 提醒

- 电费：折算金额 `< 阈值`（默认 20 元）时提醒，正文写“约 ¥15.00（30.0 度），低于 ¥20.00，记得交电费”；
- 网费：余额 `< 阈值`（默认 20 元）时提醒，正文写“余额 ¥8.00，低于 ¥20.00，记得交网费”；
- 去抖沿用 `ChangeDiff.lowAlert`：只在“从不低变成低”时提醒一次，回到阈值以上后重置；
- 两项都能在提醒设置里单独关掉；
- 判断只在**已有数据写入存档后**发生（`CampusStore` → `CampusChanges.campus`），不会为了提醒去额外查询校方系统。

## 旧设置迁移

v0.40 及以前 `electric_threshold` 存的是**度**。升级后：

- 用户确实填过该值 → 按当前电价折算成元，写入新键 `electric_threshold_yuan`；
- 没填过（仅用默认 20 度）→ 直接用新的默认 20 元；
- 旧键删除，迁移只做一次（`money_thresholds_migrated`）。

## 缴费入口

- 校园页账户卡底部：`去交电费` / `去交网费`；
- 电费、网费详情页顶部：同名主按钮；
- 打开 `CampusPayActivity`：应用内 WebView 加载校方官方页面（一卡通 / 网络自助），带 `FLAG_SECURE`；
- 只放行 `*.nwpu.edu.cn`，其它域名交给系统浏览器，避免在校方页面里被引到别处输入密码；
- 不注入脚本、不自动点击、不读取或提交任何支付字段，也不保存卡号与密码；
- 页面顶部常驻说明：缴纳在校方页面完成，本应用不代收、不代扣。

## 验证

- `node eval/run_test.mjs Step60Test`：29 项金额换算、阈值、文案与设置校验；
- `python eval/run_checks.py`：89 组 0 失败（含本项）；
- 全部 102 个 Java 源文件在 Platform 34 上编译通过。

**未验证**：真实校方缴费页在真机 WebView 中的加载与支付流程、真实电价、缴费后余额刷新。这些必须由本人在真机和校园网下确认。若校方缴费页要求单独的一卡通支付密码或短信，那是校方页面自己的流程，App 不参与也不记录。
