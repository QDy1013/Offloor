# 端侧小模型（v0.34）

“AI 识别”现在可以选“本机小模型”：拿不准的消息交给手机上运行的小模型复核，消息不出手机、不需要密钥、不计每日请求上限。云端接口照旧可用，两者二选一。

## 怎么用

更多 → AI 识别 → “用哪个模型复核”选“本机小模型” → 点“下载模型”（默认只在 Wi-Fi 下下载，可打开“允许用移动数据”）或“从文件导入 .gguf” → 打开总开关 → “测试连接”。

- 推荐模型：Qwen2.5-1.5B-Instruct 的 Q4_K_M 量化，约 1 GB。下载地址可以改，任何 llama.cpp 能读的 GGUF 都可以导入；Qwen3 系列会自动加 `/no_think` 并去掉思考段。
- 模型文件不在安装包里，安装包只多一个约 8 MB 的推理库。模型存放在应用专属目录，卸载时一并删除。
- 超过 1 GB 的文件会提示“偏大”，超过 1.5 GB 直接拒绝。
- 截图识别需要看图模型，本机模式下不可用，设置页和分享页会说明；分享的文字照常按规则出卡，再排队交给本机模型复核。

## 实现

| 部分 | 文件 | 说明 |
|---|---|---|
| 推理库 | `android/native/offloor_llm.cpp`、`CMakeLists.txt` | llama.cpp（固定 v0.9.0，提交 `cd959ba`）静态链接成单个 `liboffloor_llm.so`；只用 CPU，贪心解码，可选 GBNF 语法约束，可从另一线程取消 |
| 编译 | `android/build_native.py`、`android/build.py` | 有 NDK 时自动编 arm64-v8a（ARMv8.2 + dotprod，16 KB 页对齐）并放进 APK 的 `lib/arm64-v8a/`；没有 NDK 照常打包，本机模型显示不可用；`--require-native` 用于发布 |
| Java 入口 | `LocalLlm.java` | 加载前检查 CPU 是否有 `asimddp`，旧手机直接显示不支持而不是闪退；UTF-8 字节数组进出，避开 JNI 对表情字符的限制 |
| 纯逻辑 | `LocalLlmCore.java` | 复核输出语法：恰好 n 项、编号 1..n、字段齐全、截止时间只能是空串或 `yyyy-MM-dd HH:mm`、各字段有长度上限；GGUF 文件头校验；思考段清理 |
| 模型文件 | `LocalModelStore.java` | 系统下载管理器下载或从文件导入，先写临时文件，校验文件头和大小后再替换 |
| 复核流程 | `AiClient`、`AiJob`、`AiConfig` | 本机模式每批 3 条（云端 8 条），正文截到 400 字；后台任务不要求联网；系统叫停任务时取消生成；输出不完整按“被拒”停放，不反复重试同一批 |

模型输出照旧经过 `parseVerdicts` 的约束：截止时间必须能由本机解析或原文逐字证据得到，地点、提交方式、携带物必须是原文片段，所以小模型编造的内容写不进卡片。

## 验证

- `python3 -I eval/smoke_local_llm.py`：在电脑上用同一份源码编出本机版推理库，加载随机权重的微型 Qwen2 结构模型（词表取自 llama.cpp 自带文件），检查加载、语法约束输出、缓存清空、中途取消、超长报错和重复释放，18 项。权重是随机的，只验格式不验内容。
- `android/test/Step55Test.java`：语法结构、文件头、思考段、批量和大小上限，27 项，已接入 `eval/run_checks.py`。
- PR 检查会安装 NDK r27c，编出 arm64 推理库并确认它在测试包里，测试包作为 `preview-apk` 上传。

**尚未验证（需要真机）**：arm64 推理库在手机上的加载与速度、1.5B 模型的实际复核质量和耗电、下载管理器在各厂商系统上的表现、设置页在窄屏上的布局。推荐模型的下载地址和文件大小也需要在能访问 ModelScope 的网络下核实一次。
