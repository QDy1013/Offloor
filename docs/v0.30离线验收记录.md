# v0.30 离线验收记录

2026-11-09。本次把 16 项规划中可在电脑完成的代码、回归、评测和打包工作落实为候选版。功能实现不等于真实使用已验证。

## 已改变的使用行为

损坏或截断的存档不再半加载、再用残缺数据覆盖；优先读取有效备份，保留损坏副本，无法恢复时暂停自动覆盖。用户可在“存档与恢复”明确重建。

改期和取消会留下历史。无法确定对应哪一张卡的变更会保留候选关系，重启后仍能选择对应事项或忽略整条通知；取消卡留在可恢复记录中。乱序到达的旧通知不覆盖更新的修订。

AI 请求绑定消息、卡片状态、群设置和个人档案；过期结果不回写。重复响应编号不接受，漏回条目保留重试，拒绝和重试耗尽可见。AI 的地点、渠道、携带物必须能在原文找到；时间必须有本机解析或逐字证据。没有可靠发送日期的截图，其“明天”等时间始终待本人核对。

AI 请求每天默认最多 30 次，可改为 1–500，失败与连接测试也计数。每次网络发送前先持久化计数，达到上限保留队列。tokens 只统计服务端已经返回的用量，不能等同费用预测或服务端账单。

API Key 用 AndroidKeyStore 提供的 AES 密钥进行 GCM 认证加密；旧明文仅在加密迁移提交后移除，解密失败停用云端并提示重新填写。诊断不再记录整条平台通知原文，也不展示服务端错误响应体。图片缓存限 64 MiB、单张最多 4 MiB；下次启动、运行队列或收到图片时整理：孤立图片一天后清理，七天前的图片请求保留失败说明并要求重新分享。

校园账号切换先验证数据、再保存新快照；课表和成绩写入账号标记，旧账号快照不会因清理被打断而出现在新账号下。已有失败保留、明确空结果和分页合并检查一并纳入统一运行。

桌面性能使用同一台电脑、JDK 21.0.12.1、同 8086 条消息。基线 process p95 为 0.149199 ms、p99 为 0.349800 ms；候选 p95 为 0.154000 ms、p99 为 0.350299 ms。单次 JVM 回放没有隔离后台负载和 JIT，不宣称提速；也不包含磁盘、UI、网络、Android 调度与耗电。

## 留给外部环境的验收

1. 真机同签名覆盖安装，既有卡片、待核对和备份恢复；低存储/强制停止时不误覆盖。
2. QQ/微信/平台实际通知、通知栏扫描、锁屏和重启后的重复通知；对账是否漏卡或重卡。
3. vivo 等实际手机的自启动、后台限制、JobService 停止/替换及跨日预算恢复；主线程耗时、内存、耗电与手势交互。
4. 原生 Keystore 的首次迁移、进程重启、密文损坏和密钥失效；不把 JVM 密码学通过当作系统迁移通过。
5. 真实云接口的认证、限流、格式差异、图片质量、拒绝与 token 报告。此次未读取个人接口密钥、未作付费调用。
6. 学校账号的登录、切换、失效、空数据、分页和后端变更。浏览器构造页通过不代表学校服务仍兼容。
7. 本人日常使用及之后真实用户样本，再谈比赛中的有效性和泛化结论。

没有设备或账号的部分保留为待验项，不因此阻塞代码、检查和测试包交付。正式渠道不在这轮自动替换。
